# Asurada 赛中电台播报审计

## 正常播报入口

策略先从当前快照选主指令。共享语音服务再检查有效性、优先级、当前播放和待播槽。主动播报、车手问答、复述与可选人格共用同一个播放所有者。界面显示的策略候选比实际开口多。

| 播报出处 | 已接入的内容与条件 |
|---|---|
| 赛道管制和稳定性 | 本区黄旗「减速，禁止超车」、安全车相关的「赛道管制」、车辆动态失稳。档位最高。代码预留了 `RED_FLAG` 的最高档，但本次没有找到主动生成该代码的分支。 |
| 进攻 | 窗口形成、可执行时给动作、手动进攻模式的提示与暂缓、适用时撤回、位置结果反馈。对象、时机、攻防状态变化会撤掉旧建议。结果反馈最低档。 |
| 防守 | 即时后车压力、带后车身份与赛段的接近预判。持续按当前目标和窗口校验，后车变化、几何依据失效或风险升级可撤回。 |
| 进站 | 轮胎磨损触发进站窗口；正常轮胎管理属于普通通知。已播过的进站建议可后续坚持、因新证据修正或承认误判。车损修理、罚时、拖一圈的后果可问。实际进站和换胎的确认也用于证据链。 |
| 车损与资源 | 前翼按左右侧受损及百分比报，持续损伤去重。临近合适弯段可给入弯动作；高速弯补偿要求频道空闲且无攻防，有足够提前量时才与首报合说。独立轮胎损伤、低燃油及适用时的节油短句、低 ERS。瞬时前轮负荷仅记录。 |
| 手动驾驶辅助 | 刹车点提醒、提前或延后、取消与状态查询；开关入弯档位提醒和查询其状态。依配置及当时所在赛段，普通自动驾驶时未必开口。 |
| 车手主动问答 | 前后车差距、双方 DRS、轮胎情况及磨损趋势、燃油与 ERS、车身与前翼/底板/发动机、天气、赛道管制、罚时及进站状态。可问当前策略、为何攻防或进站、下圈重点、风险与后果。收到停止或取消时走控制路径；复述只从符合条件的已完整播放消息中取。 |
| 人格和驾驶经验 | 超车、最快圈、跑宽、轻碰或严重撞击、情况不明、确认恢复、带伤完赛及完赛反馈；玩笑、接梗及单梗撤回；可把已问过的长解释留到低负荷直道，适用时引用个人制动参照。需人格、H 档、赛况与证据符合相应条件。 |
| 赛后 | 使用明确查询获取复盘。圈速/赛段对比也有独立历史分析能力，本场未覆盖。 |

清单按代码入口盘点。当前目录共注册 21 项结构化读取、20 项解释、14 项控制和 2 项历史分析能力，其中一部分控制没有语音回复。策略允许动作由 [session_router.py](/Users/sn5/Asurada/asurada-core/src/asurada/session_router.py) 决定。调度排序在 [output_contracts.py](/Users/sn5/Asurada/asurada-core/src/asurada/output_contracts.py)，入口在 [output.py](/Users/sn5/Asurada/asurada-core/src/asurada/output.py)，可问能力见 [capability_definitions.py](/Users/sn5/Asurada/asurada-core/src/asurada/capability_definitions.py)。

## 优先级怎么落到实际播放

| 顺位 | 内容 |
|---|---|
| 4 | 黄旗、安全车、动态失稳等。能抢占可取消的低级任务。旧句确认停音后才释放播放所有权。 |
| 3 | 主动攻防、进站窗口、手动刹车点和档位；同档再比数值，例如可执行进攻 94、刹车 93、防守 92、档位 91。进攻预告的数值可为 72，但档位仍高于普通车损。 |
| 2 | 车手问答和复述。主动用户停止控制是另一路径。 |
| 1 | 普通轮胎、前翼、燃油、ERS、轮胎管理和进站跟进。前翼高速补偿 60，只有中性赛况才加入。 |
| 0 | 人格可选表达、个人习惯、延后理由、部分进攻结果。一般只用电台空闲段。 |

同档高分本身通常只影响排队。播放中抢占还要求紧急档、显式 `interrupt`、战术对前翼补偿让路或结束被普通消息盖过的可选人格，并且来句排序更高。当前策略会根据战术锁定给普通类消息附加 `interrupt`，因而车损的实际抢占档会随赛况改变。旧句也可因场景失效直接停止，此时可能没有下一句。

主动策略待播通常最多 3 秒，目标绑定的防守最多 1 秒，可选人格 2 秒。防守开播前还扣除实际排队时间，并检查动作词和缓冲是否赶得上预计接近点。已有的共享服务回归覆盖过期任务、发布快照变更、抢占等待停音、重连和停止。真实回放的 PCM 时钟是软件停音证据，耳麦仍需实测首音和尾音。

## 真实场次与证据范围

使用吉达真实游戏比赛的 19,116 个结构化快照，比赛 UID `1476455955304844120`。按归档顺序重算策略和正常播放调度。数据含闪回，逐句表保留比赛秒和闪回代数。输入为解码快照，播放时钟使用该次 Piper 试听的 PCM 句长；离线未经过耳麦，也没有插入虚构的车手 PTT、询问或黄旗。以本机 18:46 固定的源码副本重跑，源码与赛道资源哈希在同目录。回放期间工作区另有防守位置描述改动，整场数字对应固定副本。战术 LLM 在本次回放关闭。配置为人格开启、隔离关系档案。

共 **41 次开口、33 次完整、8 次截断**。截断来自两次失稳抢占、一次前翼告警抢前翼、四次进攻条件失效和一次防守条件失效。三条进攻预告在 1 秒内停音。5 个待播任务因过期取消，过期 ID 没有重新开播。按句长及停音帧重建的音轨没有句间重叠。

| 这场实际开口 | 完播 | 截断 | 实际占用 |
|---|---:|---:|---:|
| 动态失稳 | 8 | 0 | 10.78 秒 |
| 前翼损伤或对应弯段动作 | 14 | 3 | 104.95 秒 |
| 进攻预告 | 7 | 4 | 29.03 秒 |
| 防守 | 2 | 1 | 7.41 秒 |
| 轮胎损伤 | 2 | 0 | 6.59 秒 |

- **紧急抢占正常。** 第 4 圈 321.692 秒和第 16 圈 1558.800 秒，两次失稳在当前帧让车损停止并立即启动。第 16 圈右前翼说了 2.203 秒就被抢占，短句最重要的部位与数字有可能还没交代完。紧急失稳均跑完整句。本场没有实际黄旗、安全车、PTT 或前翼高速补偿开播，专项遵循独立软件回归。
- **普通车损会打断普通车损。** 第 4 圈 323.086 秒重开左前翼 88%，说到 3.203 秒被右侧 55% 的前翼播报打断。左侧随后第三次开口并说完。左侧优先级 71、右侧 72；策略的战术状态可附带普通类的 `interrupt`。这是可听见的重复，不是过期任务原 ID 复活。新侧读数适合接在当前句之后，或在开口前合并。明确危险升级才值得抢断。
- **撤回能防止过期指令，但一截就听不出动作。** 第 8 圈 815.071 秒的进攻只说了 0.500 秒，第 9 圈 916.359 秒那次更短，只有 0.295 秒，两处都没有下一条抢占；停止原因是攻窗失效。第 2 圈的安东内利防守也因窗口变化在 1.199 秒停音。这个问题应从开口前的可用时长和动作词位置解决。
- **前翼占用过多。** 17 次前翼开口含不同严重度、换胎后未维修、闪回重入和命名弯段动作，合计约占本场实播时间三分之二。优先减少可延后的通用尾句和同一受损过程中的抢断重报。威胁提示没有在这场压住失稳，普通车损之间仍会互相抢。

## 轮胎磨损、轮胎损伤、前翼损伤

- F1 25 解码分别读取四个浮点轮胎磨损、四个字节轮胎损伤、两个独立字节的左右前翼损伤。轮位是左后、右后、左前、右前。正常轮胎查询使用四轮磨损的平均值，主动轮胎警告选最高的单轮损伤读数，主动前翼告警使用各自左右侧翼值。总览车损查询目前取左右前翼最大值，口头省略了“较严重一侧”，很容易被听成整个前翼的同一读数。用同一帧执行真实结构化问答，轮胎回复说「当前 C3，磨损 30.2%」，车损总览在同一句组中先说「前翼 31%」再说「右前轮损伤 35%」，这是车手确实可能听乱的另一个入口。
- 第 12 圈比赛秒 1218.648，右前轮损伤字段 35%，右前轮磨损字段也为 35%，四轮平均磨损 30.25%，右前翼为 31%。播的是右前轮 35%。第 15 圈比赛秒 1532.698，右前轮两项都是 48%，四轮平均磨损 42%，右前翼仍为 31%。第 16 圈 1556.598，换胎后四轮两个字段均为 0%，右前翼仍为 31%，主动报了前翼。
- 全场 19,116 帧的四轮磨损与四轮损伤逐轮数值完全相同，其中 18,313 帧有非零值。两路源字段分开，遥测归档里的轮胎数据却无法支持“发生了独立于磨耗的碰撞胎伤”。现有把 35%/48%直接叫右前轮“损伤”，没有交代读数含义，是实质的表达歧义。此场未见轮胎数值和前翼数值交叉使用。样本不代表 F1 25 每场都这样。另用互不相等的字节夹具对解码做了隔离检查，四轮磨损、四轮损伤和左右前翼分别读出预设值。
- 原句前置「注意」以及连续的「右前轮损伤」「右前翼受损」，把部位留在一次很短的语音差异里。前翼句后半又提「前轮抓地」，进一步强化错听成轮胎的可能。

| 场景 | 同帧推荐表达 |
|---|---|
| 正常胎耗 | 「四条轮胎，平均磨损约百分之三十。」若局部明显，补具体哪条胎的磨损值。 |
| 轮胎损伤与磨损在这段证据中一致 | 「右前这条胎，磨损百分之三十五。」如果车手追查两项，可展开「轮胎损伤读数也是三十五，暂时无法区分额外损伤。」 |
| 独立轮胎损伤有额外证据 | 「轮胎受损。右前轮，百分之三十五。」先让车手听到是轮胎。 |
| 右前翼 | 「右前翼受损，损伤程度百分之三十一。」保留原语序。若有对应赛段行动价值，再接一条短动作。 |
| 同时询问两项 | 「右前翼受损，损伤程度百分之三十一。四条轮胎平均磨损约百分之三十。」不同部件分句，百分比贴着自己的指标。 |

## 吐字复核

回放和候选音频使用同一 Piper 中文模型。代码里的战术播报可直接走平台后端，紧急或补偿在缓存不可用时也可能走备用后端。本机无启动环境变量时解析到 MacOSSayBackend，所以试听结论只对应本次 Piper 样本，实际服务的后端要从启动环境和开播记录确认。候选均用完整 PCM 分句试听，另外用本机 Whisper base 按中文盲转写。它是关键字可辨性提示，分不开同音字时应以真人为准。原句和候选的整体 RMS 相差约 0.7 dB，所有样本均无满幅采样。没有证据指向这个对比中的音量突变或削顶。 [音频电平](clarity-audio-levels.json)旧前翼样本的开头未认出「右前翼」，但识别出百分之三十一。旧轮胎句同样未稳定识别「右前轮」。按类别拆句后，候选轮胎句可辨出「右前轮」及百分比；胎耗句可辨出轮胎、平均和数值。轮胎磨损的备选用「右前这条胎」让识别稳定得到「这条胎」，「右前」和「磨损」仍有不稳定。缩短的前翼句仍未让转写识别出完整部位。保持文本次序的同时，右前翼仍须做同声线真人听辨。这次交付的是审计和候选试听。另抽测五条风险、攻防和轮胎完整 PCM，短句「动态不稳定」的后半可辨，防守「守主直道」被转写为「收住直到」，两个较长攻防句的直道动作或车手名有误识。百分比在相同声音下更稳定。现场测试应同时听部位、动作、姓名和数字，避免仅凭数字正确判通过。 [其他播报盲转写](other-calls-ASR.json)

```sh
audit=output/radio-audit-jeddah-2026-11-21
archive=/tmp/asurada-personality-live-zhlj_11k/logs
snapshot="$(cat "$audit/source-snapshot-path.txt")"
ASURADA_ASSET_ROOT="$snapshot/assets" PYTHONPATH="$snapshot:$PWD/asurada-core/scripts" asurada-core/.venv/bin/python "$audit/replay_audit.py" "$archive"
asurada-core/.venv/bin/python "$audit/render_timeline.py"
asurada-core/.venv/bin/python "$audit/render_highlights.py"
asurada-core/.venv/bin/python "$audit/verify_damage_fields.py" "$archive"
asurada-core/.venv/bin/python "$audit/clarity_sample.py"
```
