# Asurada 赛中低延迟问答优化方案

状态：待验证的设计提案。此次只记录方案，不表示已实现或已达标。

## 1. 出弯后预计算常见答案

赛段关闭后，在不占用实时策略主链的后台任务中，将当前圈与上一有效圈或明确选定的参考圈按赛道里程对齐，比较同一弯或同一赛段。缓存可复用的简短证据卡：刹车和油门的位置及变化、转向输入、出弯速度、分段时间差，以及当前圈、参考圈、覆盖情况、生成时间和适用状态。常见问题可直接读取证据，例如「刚才这个弯比上一圈慢在哪一段？」。缓存按会话、时间线、赛道布局、圈和赛段区分；出现回闪、换参考圈或证据修正时使旧卡片失效。过期卡片不能用来回答当前状态。

收益是把常见问答的计算提前到出弯后；代价是每个有效赛段都需要少量后台算力，且要管理缓存一致性。后台任务必须有界，资源紧张时优先跳过预计算，不挤占紧急播报。

## 2. 少见问题按需做有界的本地分析

用会话、圈、赛段和里程索引定位回答所需的最近遥测，只读相关弯和圈，不扫描整场。先解析问题中的目标和基准，再由本地确定性逻辑完成对齐、比较和度量。任务应有明确的时间、输入规模和并发预算；超出预算时返回已核实的局部信息，或明确说明暂不能比较。收益是覆盖未提前缓存的问法；代价是这类问答仍有计算开销，需要把范围和超时控制清楚。

## 比较与播报边界

- 比较需确认同一赛道布局、相同赛段起止位置、圈有效、遥测覆盖足够，且没有暂停、回闪或明显采样缺口。轮胎、赛道湿度、交通、黄旗、出入站等条件明显不同时，不直接作等条件归因；需要比较时先说明差异。
- 参考圈缺失、信号不新鲜或只覆盖半个弯时，不猜数值或原因。可以说「刚才这段还没采全，暂时不能和上一圈比」，或仅报告已有的可验证事实。
- 黄旗、紧急失稳等继续走原有确定性独立通路，不等待索引、预计算、检索或模型。问答里的事实和结果由本地比较产生；模型可选，只用于理解问法、组织已测证据的表述。「油门晚开、出弯速度低」可以是同时观察到的变化，不能无证据地说一项导致另一项。

## 验证指标

分开记录常见问题的缓存命中、未命中，以及少见问题的按需分析。记录「出弯/赛段关闭 → 有效证据卡可读」与「用户说完 → 首句有用音频实际开始播放」的 P50、P95、P99；后者不把排队成功、确认音或无信息的占位语当作完成。并记录样本数、数据不足率、缓存命中率，以及并发问答时紧急播报有没有被延迟或丢失。先用同一批回放建立前后对照，再单独采集实跑数据校验。当前没有已验证的阈值目标、延迟结果或实跑结论。
